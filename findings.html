03 / FINDINGS & REMEDIATION

Make input
stay as data.

The demonstration shows the impact of an unsafe HTML sink and the value of rendering untrusted content as text.

OBSERVATION

Reflected XSS behavior

In vulnerable mode, the page reads a value from the URL query string and places it into an HTML parsing sink. A payload containing an image with an error handler can create an element and run its handler when the image fails to load. The value is reflected immediately and is not stored.

In safe mode, the same string is assigned with textContent. The browser displays the angle brackets and handler text literally; it does not parse them as HTML.

VULNERABLE PATTERN

HTML parsing sink

result.innerHTML = userInput;

Untrusted text becomes markup. Avoid this pattern for user-controlled values.

SAFER PATTERN

Text rendering

result.textContent = userInput;

Text is rendered as text, without interpreting markup. Validate input for the application’s rules as an additional control.

REMEDIATION

Layer the controls

  • Prefer safe DOM APIs: render untrusted values with textContent or framework auto-escaping.
  • Validate by purpose: allow only expected formats, lengths, and characters where the feature needs restrictions. Validation alone is not an output-safety control.
  • Encode for the output context: HTML text, attributes, URLs, CSS, and JavaScript have different rules. Use a trusted encoder or safe API for the exact context.
  • Reduce impact: deploy a restrictive Content Security Policy and use secure cookie settings as defense in depth.

Limitations

This is a client-side educational simulation of reflected XSS, not a full server-backed application or a comprehensive security assessment. Results apply only to the included page and browser behavior observed during the demonstration. No persistent stored-XSS behavior is implemented.

Conclusion

The vulnerable rendering path turns query text into executable browser markup. Treating the value as text prevents that interpretation in this output context. The safe rendering rule is the primary fix; validation and browser policies add further protection.
