02 / METHODOLOGY

Test locally.
Explain clearly.

The exercise uses a self-contained page and harmless proof-of-execution payloads. It is intended for this local demonstration only.

SCOPE

Authorized target

The target is the included demonstration page opened by the student in their own browser. No external site, service, or user data is involved.

QUESTION

What is tested?

Whether query-string input is inserted into an HTML parsing context as markup, and whether a remediation renders the same input as plain text.

REPRODUCE

Run the demonstration

  1. From the repository folder, start a static server with python -m http.server 8000.
  2. Open http://localhost:8000/demo.html in your browser.
  3. Choose the vulnerable or safe mode, then use the built-in harmless payload or enter text of your own.
  4. Observe that the vulnerable mode interprets an event-handler payload, while safe mode displays it as text. Reset the page between trials.

Safety: The vulnerable mode is deliberately unsafe and should remain confined to this local teaching page. Do not deploy it to a public host. The portfolio pages are static and do not execute submitted values.

Test cases

  • Ordinary text: Hello, reviewer
  • Markup characters: <tag>&"'
  • Harmless event test: <img src=x onerror=alert('XSS')>
  • Empty and whitespace-only input

Expected secure behavior

Input remains data. It is shown literally, with no new element or event handler created. A Content Security Policy is useful defense in depth, but does not replace safe rendering.
